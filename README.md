# Cloud Lab 04: статикалық сайтты Yandex Object Storage-ге орналастыру

Қазақ тіліндегі бір беттік сайт және зертханалық жұмысқа арналған есеп нұсқаулығы. Сайт таза HTML, CSS және JavaScript-пен жасалған; құрастыру қадамы қажет емес.

## Жергілікті тексеру

`index.html` файлын браузерде ашуға болады. Endpoint тестері, навигация және орындалу чек-листі браузерде жұмыс істейді. Google Fonts пен басты беттегі сервер фотосын көрсету үшін интернет қажет.

## Yandex Object Storage-ге жариялау

1. `index.html`, `error.html`, `styles.css` және `script.js` файлдарын бір жергілікті бумада ұста.
2. Yandex Cloud консолінде бірегей атауы бар Bucket құр. Bucket-тің жалпыға қолжетімділігін конфигурациялағанда тек **оқу** құқығын бер; жазу мен жоюды шекте.
3. Төрт файлды Bucket түбіріне жүкте. Бұл жобадағы файлдарға жеке сілтемелер салыстырмалы, сондықтан олар бір деңгейде тұруы керек.
4. Bucket параметрлерінен статикалық веб-сайт хостингін қос. Негізгі құжатқа `index.html`, қате құжатына `error.html` орнат.
5. Консоль көрсеткен нақты Website Endpoint URL-ын көшіріп, сайтты браузерде тексер. Жоқ файлға өтіп, қате құжатын да тексер.
6. Скриншоттарды төмендегі тізім бойынша түсір. Қауіпсіздік үшін сайтқа құпия деректерді немесе жариялауға болмайтын файлдарды жүктеме.

Консольдегі атаулар мен қолжетімділік баптаулары өзгеруі мүмкін. Bucket-ке жалпы оқу құқығын ашқанда ішіндегі **барлық** объект жария болатынын ескер. HTTPS немесе жеке домен қажет болса, Yandex Cloud CDN сияқты қосымша шешімді бөлек баптау керек.

## Есепке арналған құрылым

- **Тақырыбы:** Yandex Object Storage көмегімен статикалық веб-сайтты орналастыру.
- **Мақсаты:** бұлттық сақтау қызметінде HTML, CSS және JavaScript файлдарынан тұратын статикалық сайтты жариялау, негізгі және қате құжаттарды баптау, Endpoint арқылы нәтижені тексеру.
- **Файл құрылымы:** `index.html`, `error.html`, `styles.css`, `script.js`.
- **Bucket атауы:** өзің жасаған нақты атауды жаз.
- **Website Endpoint:** Yandex Cloud консолінде көрсетілген нақты URL-ды жаз.
- **Нәтиже:** тек өз аккаунтыңда орындап, браузерде тексерген қадамдарыңды және нақты скриншоттарыңды енгіз. Бұл репозиторий Yandex Cloud-тағы орналастыруды немесе скриншоттарды өздігінен растамайды.

### Есепке қосылатын скриншоттар

1. Жергілікті сайт файлдарының құрылымы.
2. Bucket атауы мен параметрлері.
3. Bucket ішіндегі жүктелген объектілер.
4. Қоғамдық оқу рұқсаты және шектеулі жазу/жою баптауы.
5. Static Website Hosting: `index.html` және `error.html`.
6. Консольдегі Website Endpoint URL.
7. Endpoint ашылғандағы негізгі веб-бет.
8. Жоқ мекенжай сұралғандағы қате беті.

### Қорытынды үлгісі

Зертханалық жұмыста статикалық веб-сайтты Yandex Object Storage-де орналастыру қадамдары орындалды. Bucket құрылып, сайттың HTML, CSS және JavaScript файлдары жүктелді. Негізгі және қате құжаттарға арналған хостинг параметрлері бапталды. Жалпыға қолжетімділік тек оқу құқығымен шектелді. Website Endpoint арқылы негізгі бет пен жоқ мекенжайдың жауабы тексерілді. Нақты орындау нәтижесін өз скриншоттарыңмен раста.

## Бақылау сұрақтарына жауап

1. **Object Storage дегеніміз не?** Деректерді объектілер түрінде сақтап, API арқылы файлдарды алуға және жүктеуге арналған бұлттық қызмет.
2. **Bucket дегеніміз не?** Объектілер сақталатын, атауы бірегей логикалық контейнер.
3. **Object дегеніміз не?** Bucket ішінде сақталатын файл, оның метадеректері және объектіні анықтайтын кілті.
4. **Object Storage статикалық сайтқа неге қолайлы?** Дайын HTML, CSS, JavaScript және суреттерді серверді басқармай сақтап, HTTP арқылы береді.
5. **Неге ол динамикалық кодты орындамайды?** Бұл сақтау қызметі, қолданбалық кодты іске қосатын серверлік есептеу ортасы емес.
6. **Статикалық және динамикалық сайттың айырмасы қандай?** Статикалық сайт дайын файлдарды береді; динамикалық сайт серверде сұранысқа қарай мазмұн қалыптастырады.
7. **`index.html` не істейді?** Сайттың негізгі құжаты ретінде түбірлік адрес ашылғанда көрсетіледі.
8. **`error.html` не үшін керек?** Табылмаған ресурс сұралғанда көрсетілетін арнайы қате бетін анықтайды.
9. **Website Endpoint дегеніміз не?** Хостингтегі сайтқа браузер арқылы кіруге арналған мекенжай.
10. **Public Read Access дегеніміз не?** Кез келген пайдаланушыға объектіні оқуға рұқсат беру; жазу мен жоюды бөлек шектеуге болады.
11. **Қандай қауіпсіздік мәселелері бар?** Қоғамдық оқуға ашылған Bucket ішіндегі объектілерді кез келген адам көре алады. Құпия файлдарды жүктеме және тек қажет рұқсатты бер.
12. **Object Durability дегеніміз не?** Объектілердің ұзақ мерзімде жоғалмай сақталу ықтималдығын сипаттайтын көрсеткіш.
13. **Оның маңызы қандай?** Деректер жоғалу тәуекелін және сақтау сенімділігін бағалауға көмектеседі.
14. **Storage Class дегеніміз не?** Қолжетімділік ерекшеліктері мен сақтау құнына әсер ететін сақтау класы.
15. **Сирек қолданылатын файлға арзан класс таңдаудың пайдасы қандай?** Сәйкес қолжетімділік шарттарында ұзақ мерзімді сақтау шығынын төмендетеді.
16. **Object Storage пен виртуалды машинаның айырмасы қандай?** Біріншісі файл сақтайды; виртуалды машина операциялық жүйе мен бағдарламаларды іске қосады.
17. **CSS неге жүктелмеуі мүмкін?** Қате жол/атау, жүктелмеген объект, рұқсат қатесі немесе регистр сәйкессіздігі себеп болуы мүмкін.
18. **Неге негізгі және қате бет бөлек көрсетіледі?** Хостинг сәтті сұранысқа қай құжатты, қате сұранысқа қай құжатты беретінін бөлек баптайды.
19. **Object Storage-дің артықшылықтары қандай?** Оңай орналастыру, серверді басқармау, файлдарды тарату және шығынды оңтайландыру мүмкіндігі.
20. **Сайтты қалай тексеруге болады?** Endpoint-ті ашып, негізгі бет, CSS, сурет, JavaScript және жоқ URL кезіндегі қате бетін тексеру керек.
